DevTools

Dev Only

A built-in developer panel for monitoring, testing, and debugging toast notifications in real time. Automatically excluded from production builds.

OverviewSetupOpening DevToolsLive PlaygroundMonitor TabCreate TabSettings TabKeyboard ShortcutsImperative APIProduction SafetyAdvanced Patterns

Overview

React Toast Kit ships with ToastDevTools — a floating panel that gives you full visibility into the toast system during development. It reads directly from the Zustand store, so the state you see is always the ground truth.

📊

Live Monitor

See all active toasts with variant, position, duration, animation, and pause state in real time.

⚡

Quick Tests

One-click buttons for success, error, warning, info, loading, custom, promise, and stress tests.

🔧

Toast Builder

Build any toast configuration with a form — variant, position, animation, style, duration — and fire it instantly.

⚙️

Global Settings

Change theme, max toasts, and view registered plugins without touching your source code.

🔑

Keyboard Shortcut

Alt+Shift+D toggles the panel from any screen in your app, no button click needed.

🛡️

Zero Production Impact

The panel returns null in production. The component weighs nothing when not rendered.

Setup

Import ToastDevTools from react-toast-kit/devtools and place it anywhere inside ToastProvider. The panel must be a child of ToastProvider to access the shared Zustand store.

app/layout.tsx
1// app/layout.tsx — Next.js App Router
2'use client';
3import { ToastProvider } from 'react-toast-kit';
4import { ToastDevTools } from 'react-toast-kit/devtools';
5
6export default function RootLayout({ children }) {
7  return (
8    <html>
9      <body>
10        <ToastProvider>
11          {children}
12          {/* DevTools auto-hides in production */}
13          <ToastDevTools />
14        </ToastProvider>
15      </body>
16    </html>
17  );
18}
⚠️
Next.js App Router: Layouts that contain client hooks must be marked 'use client'. If your root layout is a server component, create a separate ClientProviders wrapper and import it there.

Opening DevTools

Three ways to open the DevTools panel:

1
Floating buttonDefault

A gradient button appears in the bottom-right corner of every page. Click it to open the panel.

2
Keyboard shortcutRecommended

Press Alt + Shift + D from anywhere in your app. This works even when the button is hidden.

3
Imperative APIProgrammatic

Call toastDevTools.show() or toastDevTools.toggle() from your own code (e.g. dev toolbar, console).

Plugin RegistryRead-only

Lists all plugins registered via registerPlugin(). Shows plugin name and description. Empty state shown when none are registered.

plugins/analytics.ts
1import { registerPlugin } from 'react-toast-kit';
2
3// Example plugin visible in DevTools → Settings → Plugins
4registerPlugin({
5  name: 'analytics',
6  description: 'Tracks toast impressions for analytics',
7  afterCreate: (toast) => {
8    console.log('[Analytics] Toast shown:', toast.variant, toast.title);
9  },
10  afterRemove: (toast) => {
11    console.log('[Analytics] Toast dismissed:', toast.id);
12  },
13});

Registered plugins appear in DevTools → Settings → Plugin Info with their name and description.

Imperative API

toastDevTools exposes a programmatic interface for controlling the panel and accessing store state from outside of React — useful in e2e tests, dev toolbars, or the browser console.

1import { toastDevTools } from 'react-toast-kit';
2
3// Open the panel programmatically
4toastDevTools.show();
5
6// Hide the panel
7toastDevTools.hide();
8
9// Toggle open/closed
10toastDevTools.toggle();
11
12// Access the current toast list (useful in tests)
13const toasts = toastDevTools.getToasts();
14
15// Debug helpers (development only)
16toastDevTools.debugInfo();          // console.group with full state
17toastDevTools.simulateError();      // fire a test error toast
18toastDevTools.simulateSuccess();    // fire a test success toast
19const store = toastDevTools.getStore(); // raw Zustand state

Development-only methods

debugInfo(), simulateError(), simulateSuccess(), and getStore() are only available when NODE_ENV === 'development'. They are tree-shaken in production bundles.

Production Safety

Auto-excluded in production

ToastDevTools checks process.env.NODE_ENV and returns null before rendering anything when not in development. No DOM nodes, no event listeners, no bundle cost in production.

If you want an explicit guard for extra safety, use the conditional pattern:

1// Only mount DevTools in development — explicit guard
2import { ToastDevTools } from 'react-toast-kit/devtools';
3
4export default function RootLayout({ children }) {
5  return (
6    <ToastProvider>
7      {children}
8      {process.env.NODE_ENV === 'development' && <ToastDevTools />}
9    </ToastProvider>
10  );
11}

Advanced Patterns

Stress testing the queue

Use the built-in Stress quick test or write your own to verify how the library handles rapid bursts of toasts, priority ordering, and queue trimming.

1import { toast } from 'react-toast-kit';
2
3// Stress-test the queue with mixed variants
4function stressTest() {
5  const variants = ['success', 'error', 'warning', 'info'] as const;
6  const positions = ['top-left', 'top-right', 'bottom-left', 'bottom-right'] as const;
7
8  for (let i = 0; i < 5; i++) {
9    setTimeout(() => {
10      toast({
11        title: `Stress test #${i + 1}`,
12        description: 'Testing multiple toasts at once',
13        variant: variants[i % variants.length],
14        position: positions[i % positions.length],
15        duration: 2000,
16      });
17    }, i * 200);
18  }
19}

Testing promise flows

The promise quick test uses a 50% random failure rate. Use the Create tab or write your own to test specific error messages, loading durations, and success payloads.

1import { toast } from 'react-toast-kit';
2
3// Test promise flow (50% fail rate)
4function testPromise() {
5  const promise = new Promise((resolve, reject) =>
6    setTimeout(
7      () => Math.random() > 0.5 ? resolve('Done!') : reject('Failed!'),
8      2000
9    )
10  );
11
12  toast.promise(promise, {
13    loading: 'Processing request...',
14    success: (msg) => ({ title: 'Success', description: String(msg) }),
15    error: (err) => ({ title: 'Failed', description: String(err) }),
16  });
17}

Inspecting toast state in Playwright / Cypress

Access the Zustand store from your test runner by calling toastDevTools.getToasts() via page.evaluate:

1// playwright
2const toasts = await page.evaluate(() => {
3  // toastDevTools is globally exported
4  return window.__REACT_TOAST_KIT_DEVTOOLS__?.getToasts() ?? [];
5});
6expect(toasts).toHaveLength(1);
7expect(toasts[0].variant).toBe('success');
